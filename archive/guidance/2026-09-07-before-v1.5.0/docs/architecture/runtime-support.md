# 运行环境状态与用户责任
日期：2026-09-07。当前用户决定取代同日早前的安装兼容方案：**只检测并提示能否运行，环境由用户管理，不区分 Conda 类型，不提供自动安装/修复承诺。**

## 产品行为
- 顶部“运行环境”打开处理器状态页；Sentinel-1 / ISCE2 与 NISAR / ISCE3 分别显示，不要求用户选择包管理方式。
- 每次打开实际检测，显示环境就绪、当前不可运行或尚未确认。失败显示缺失模块/工具、检查失败或超时，不伪装通过。
- 显示实际 Python、组件版本和检测时间，可选文件路径、重新检测或保存检测路径。
- 当前有 Pipeline 时优先检测其 Python；否则使用最近保存的对应检测路径；没有选择时明确检测应用 Python。不会扫描磁盘或猜测环境名。
- 保存检测路径只是应用偏好，不改写旧 Pipeline、科学配置或运行历史。用户需要自行在参数页指定实际用于处理的 Python。
- 改动路径清除旧状态；旧请求结果不得覆盖新选择。未检查或探测超时不能显示可用。
- 环境由用户安装、升级和修复。没有检测通过的科学环境仍可使用与其无关的检索/下载能力。

## 当前基础检查
- 使用与当前 Job 相同的 runtime_environment 构造执行环境；直接调用选定解释器，不执行 shell 激活语句。
- ISCE2：导入 isce/isceobj；stackSentinel.py 与 SentinelWrapper.py 执行 -h，检查入口及导入依赖；检查 GDAL 与 EPSG/PROJ。
- ISCE3：导入 isce3 与 nisar.workflows.insar；检查 GDAL HDF5/HDF5Image 驱动与 EPSG/PROJ。
- 读 stdout 中专用结构化结果标记，原生输出不直接展示。异常仅返回受限错误类别/缺失模块，避免泄露环境秘密。
- 外层探测最多 25 秒，TOPS 帮助调用各 8 秒。运行环境页不持续轮询/传日志，不触发数据处理。
- /compute 只报告硬件和未检查的处理器状态，不再依据 CPU 存在宣称已可运行；POST /compute/check 提供实际检查结果。

## 结果边界
“环境就绪”仅表示上述 CPU 基础依赖/入口检查通过；不代表数据兼容、DEM/模板、所有可选科学阶段、科学数值或 CUDA 验收通过。
不启用当前范围外的解缠，因此此页不无条件检查 SNAPHU；按步骤的输入/输出合同保持原有处理机制。
本轮没有新增执行前统一门禁，也没有重写现有 runtime_environment 的路径推导；不同安装布局可能被当前执行环境判为不可用，页面应如实报告。未来修复适配问题不需要引入包管理类型 UI。
