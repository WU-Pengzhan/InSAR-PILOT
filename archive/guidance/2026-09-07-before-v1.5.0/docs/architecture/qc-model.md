# 当前 QC 范围：基础检查与按需评价

用户决定暂缓解缠排障和大范围相位科学检查，近期优先取得 phase stack 并做好 Sentinel Web 页面。
这取消了旧的全面相位对照开发门槛，不取消对真实文件和真实执行状态的确认。

## 三层检查

| 层次 | 当前要求 | 页面呈现 |
|---|---|---|
| 输入/执行/结构 | 兼容数据、必需角色、可读文件、已知 shape/dtype/闭包、进程退出和实际产物 | 数据准备状态与运行步骤检查，必要失败阻断 |
| 轻量科研观察 | 复用已有 baseline/misregistration；需要栅格读取时采用明确窗口、分块或采样 | 运行详情或成果/QC 子视图，标注方法与范围 |
| 昂贵科学评价 | 整景相位对照、解缠评价、完整黄金数据数值回归等 | 当前暂缓，显示未执行/UNKNOWN 及原因 |

不能把数据缺失伪装成“科学检查暂缓”。也不能自动进行整景内存加载来获得一个合格标记。
大规模任务需资源估计、分块/采样策略和明确操作入口，留待对应页面设计。
已记录的失败保留原错误；“整景检查导致失败”未被证据确认，不作为根因写入。

## 类型与规则

QCExtractor 提取事实，QCPolicy 解释事实，QCReport 冻结评估；提取器/策略分别版本化。
每项包含 value/unit、scope、source、mask/nodata/采样方法、阈值、解释与 Run/Artifact 引用。

状态 PASS / WARNING / FAIL / UNKNOWN。未执行、不支持、缺来源和解析失败分别说明。
科学指标没有明确有效门限时不自动判 PASS；处理参数（例如 ESD 筛选阈值）不直接当 QC 合格线。
已有冻结策略保留；本轮没有关闭正在使用的门禁或重写历史 QC。

只改策略时追加报告并重算可用性，不重跑影像。
完整 Sentinel/NISAR QC 矩阵保存在历史指导中；按约定页面和产品逐项恢复具体指标开发，不作为同时实现的任务清单。
