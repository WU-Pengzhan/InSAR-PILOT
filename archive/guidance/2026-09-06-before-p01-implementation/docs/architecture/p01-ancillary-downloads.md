## 1. 当前究竟能做什么

现有 Web 已有 SLC 和 EOF 下载入口与 worker，但前轮只保存设计，没有开发新版界面，也没有真实 SLC/EOF 下载验收。因此“已有代码路径”“新版已实现”“真实下载已验证”必须分别报告。

| 项目 | 本次代码/探针证据 | 结论 |
|---|---|---|
| Web SLC/EOF | engine_download 固定 include_orbits=True，按景顺序调用 DownloadService | 有既有路径，缺 EOF 勾选合同 |
| Web DEM | download-readiness 报告 DEM Web 未接线；worker 未调 DEM 服务 | 不能声称现在能在该 Web 页面下载 DEM |
| DEM 核心 | DemCoveragePlanner、Cop30AwsDemService、OpenTopographyDemService 已存在 | 可以复用底层，不能原样满足新范围 |
| 旧覆盖规划 | 只收集 AOI 自动选中的 burst；单 burst 最多再加一个邻居，缺数据时可退回 AOI | 不满足全 IW/全 frame；需替换覆盖策略 |
| EOF 平台 | OrbitDownloadService._mission 识别 B/C，否则 A | 1D 本地探针返回 S1A，必须修复；不是已下载错误 EOF 的证据 |
| 已有 SLC 复用 | 任意非空目标文件直接 skipped | 1 字节无效 ZIP 探针也 skipped；现有完成判据不足 |
| SLC 发布 | aria2 退出 0 且 partial 非空后重命名 | 本层未核对源长度、ZIP CRC 或提供方摘要 |
| DEM Range | 默认 8 段、瓦片顺序下载；验证 206、区间和长度，缓存后 GDAL 检查 | 比只检查非空更完整，但缺跨会话对象版本约束及统一调度 |
| EOF 匹配 | 既有文件按文件名和单个成像时间匹配；新增文件取新增集合最后一项 | 应核对 XML、卫星、产品类型和完整成像时段，不能只按目录/文件名 |

代码起点：download/download_service.py、dem_service.py、cop30_service.py、orbit_service.py、network.py、session_auth.py，application/engine_download.py，services/iw_recommendation.py 和 dem_preparer.py（均位于 src/insar_pilot/ 下）。

本地探针只在独立临时目录写入一个假文件，自动清理；未访问用户 SAR 输入，也没有启动下载 worker。证据：artifacts/p01-dem-network-2026-09-06/local-probes.json。

## 2. 同一页面的选项与流程

三个入口“仅下载 / 从选择创建工程 / 添加当前工程”复用同一提交清单：

~~~text
所选完整 SLC       N 景                    必选
[✓] 下载对应 EOF  精密轨道，按卫星和成像时段匹配
[ ] 下载覆盖 DEM  整景联合范围 + 安全余量
    数据源：Copernicus GLO-30（默认建议）
    范围：完整场景；不随当前 AOI/burst 缩小
    安全余量：20 km（建议初值，可向上调整）
    预览：SLC 外包范围 / 带余量范围 / 瓦片数量 / 大小估计
[保存选择，稍后下载]  [保存并开始下载]
~~~

- EOF 默认勾选以延续既有行为；DEM 为新增的大体积操作，默认不勾选，用户勾选后与本批次一起自动执行。默认值是本次设计建议，已提交计划永久保留当时选项。
- 未勾选角色显示“未请求”，不能显示失败、缺失下载或算入完成分母。EOF/DEM 任意组合都支持；不勾 EOF 不妨碍勾 DEM。
- DEM 勾选后预览范围和容量，未解析元数据时标“估计，待 SLC 完成后核对”。开始按钮明确包含勾选角色；不在后台额外加入未勾选数据。
- 缺 DEM 工具或源覆盖时，只阻断包含 DEM 的开始动作；允许取消勾选继续获取 SLC/EOF。保存选择仍可用。
- 正常进程：SLC 获取/校验 → 对应 EOF → 全批次 SLC 范围核对 → DEM 瓦片下载、拼接、检查及发布。
- 依赖关系以事实为准：DEM 覆盖需要所选 SLC 元数据，不需要 EOF 文件。EOF 暂未发布或失败时，已具备完整几何的 DEM 可以继续；各角色状态独立，批次显示未全部完成。
- 部分 SLC 失败时保留已完成文件和 EOF，DEM 标“等待完整场景范围”；重试缺失场景后继续。若用户要只处理成功子集，创建新的显式子集计划，不能把较小 DEM 标为原全集覆盖。
- 下载完仍能从批次详情“补充 EOF / 补充 DEM”，复用已有 SLC 与瓦片；建立新获取计划/尝试，原终态计划不改写。
- EOF 精密轨道尚未发布时显示“精密轨道暂不可用”；不把不存在当认证错误，不默默换成 restituted，也不无限轮询。保留手动重试入口。

## 3. DEM：整幅宽联合范围 + 余量

### 3.1 计算规则

1. 冻结选择中的全部 Sentinel IW SLC 身份，不受当前查询 AOI、表格分页、参考景或 burst 选择影响。
2. 下载前使用每景完整目录 footprint 估算外包范围。下载完成后，从 SAFE manifest/annotation 的全部 IW1/IW2/IW3 全景 geolocation 点核对真实范围；只读取元数据，不加载巨大测量影像。
3. 对全部所选日期/切片/frame 的完整几何取联合外包框，不取交集，不只取参考景。相邻两景按整体包住，多日期重复覆盖不重复计瓦片。核对不应因选择不同极化而丢掉某个 IW。
4. 对每个完整几何边界进行测地距离扩展，再求保守外包框；建议向四周留 **20 km**。不能把“20 km”简单固定换算为经纬度增量，高纬度按真实测地距离计算。
5. 向外对齐最终源栅格网格，并列出所有相交源瓦片；输出 GeoTIFF 覆盖带余量的范围，源瓦片完整缓存。不为了贴合 AOI 裁掉外侧 IW。
6. 检查输出范围包含整个带余量目标、接缝和边缘像元可读；明确 nodata 区域。矩形包含不等于所有地形都有有效高程，内孔/源缺片须另外检查。

20 km 是保守工程初值，不是对任何地形/处理窗口都足够的科学保证。P02 仍按实际处理足迹与所需边界检查覆盖；不足时生成扩大后的新 DEM 版本，复用瓦片，不悄悄缩小处理范围。余量增加可预览，首版不提供低于建议初值的缩小选项。

完整元数据解析失败时，目录 footprint 只能保留“估算”身份；不得退回当前 AOI 并报整景覆盖成功。缺少某景完整几何则阻断最终覆盖确认，允许修复/重新解析或明确移除该景创建新计划。

### 3.2 大范围与异常

- 相连两景优先生成一个足够大的 DEM，大小由地理范围决定，不因“有两景”按大小翻倍。
- 远隔区域不能静默用一个全球级 bbox 拼接。预览明确容量与瓦片数，建议按研究区拆成独立批次；不得通过收缩到 AOI 绕过限制。
- 现有 COP30 单任务最多 64 瓦片、拒绝跨日期线。首版保留明确上限；超限要求拆批，跨日期线说明暂不支持，不能改成覆盖大半个地球的范围。
- 预估磁盘包含缺失源瓦片、续传分块、拼装临时文件、拼接输出和缓存复用；未知压缩率不能当确定大小。没有足够空间时不开始大规模传输。
- 正常流程在 SLC 几何确定后才正式执行 DEM 下载；若核对范围超出原预览资源上限，显示调整后的计划并等待用户再次开始，不自动造成无界扩张。

### 3.3 数据源、缓存与高程基准

建议默认复用现有 **Copernicus GLO-30 公共 COG 瓦片**路径：无需 DEM API key，瓦片可重复利用，适合大范围而不是反复提交裁剪服务。它是约 30 m DSM，包含植被/建筑物表面，不应称为裸地 DTM。

AWS 公共 GLO-30 有未公开区域及海洋无瓦片情况。[官方说明](https://registry.opendata.aws/copernicus-dem/)并不保证任意 bbox 都有数据。404 不能统一填零；有明确海洋掩膜/来源证明时才能按标注规则处理海洋，否则报告缺瓦片/覆盖不足。其他 DEM 源只在显式选择后作为新计划使用，不能静默混合。

COP30 在当前模型中标为 EGM2008 高程。下载后保留原始参考、源版本/瓦片及处理记录；P01 发布“已获取的 GeoTIFF”。P02 使用现有准备能力生成处理所需 WGS84 椭球高程和 ISCE 文件，必须证明所需大地水准面网格存在并实际完成转换；仅改 CRS 标签或输出文件名不能算转换。下载完成不显示“可直接运行 ISCE”。

瓦片缓存按源、tile ID、对象版本/长度/摘要和校验依据识别；并发使用同一瓦片需互斥。派生 DEM 身份包含场景集版本、覆盖几何、余量、源版本、网格/插值、垂直参考和工具版本。扩大范围复用已有完整瓦片，输出新版本保留旧文件。只有成功校验/发布的文件可进入可用 Library 引用。

## 4. 网络和完整性评估

### 4.1 当前方案

SLC 采用 ASF/Earthdata 认证加 aria2c；一个批次逐景处理，单文件固定 4 连接、4 分片、最小分片 1 MiB，启用续传。aria2 单次 max-tries=1，外层最多再试 2 次；缺少按 HTTP 状态区分、Retry-After 和全局资源预算。

COP30 为逐瓦片、每瓦片默认 8 个 requests Range worker，区间失败最多 3 次、线性等待。区间与拼装长度检查有价值，但保存的分片没有绑定远端 ETag/版本；同长度对象更新可能错误续用。GDAL checksum/解码检查用于可读性，不是提供方密码学摘要验证。

NetworkConfig 有直连/环境代理/手动代理，但默认直连忽略环境代理；Web worker 没有把网络选择串到 SLC/EOF/DEM 的统一合同。EOF 调用 sentineleof 未传递该 NetworkConfig。不能认为“电脑开了代理，所有下载就自动走它”。

### 4.2 本次限量实测

从当前 WSL 直连读取公开 COP30 N34 E108 瓦片的不同字节区间。1/4/8 路各 2 次，每次总量 4 MiB，合计 **24 MiB**；没有读取凭据，没有 ASF/SLC/EOF 实际下载，没有完整 DEM 拼接或发布。

| Range 并发 | 两次有效吞吐（MiB/s） | 平均 |
|---|---|---|
| 1 | 1.365 / 1.551 | 1.46 |
| 4 | 1.466 / 1.499 | 1.48 |
| 8 | 1.838 / 1.664 | 1.75 |

所有探测区间的 HTTP 206、Content-Range、长度和 ETag 与 HEAD 一致。脚本/原始结果：artifacts/p01-dem-network-2026-09-06/network_probe.py、network-probe.json。

小样本中 8 路约快两成，4 路和 1 路接近。每次仅 4 MiB，含新连接/TLS 开销，样本只有两次、区域和时段单一，未测浏览器、aria2、ASF 认证链路或长时稳定速度。因此不能承诺倍速、跑满用户宽带，不能用这个数给 SLC 估时。

### 4.3 建议保留引擎，补调度和可靠性

| 方案 | 取舍 | 建议 |
|---|---|---|
| 保留 aria2c | 已有断点/文件分段与取消链路，易保持历史；当前固定参数和校验不足 | 首选，改调度/校验而非重写传输 |
| ASF 官方 Python 下载 | 官方支持复用认证会话与多进程下载；适合检索与 URL/认证集成 | 保留作集成/对照，不因官方提供就假设更快 |
| 自写全套 SLC Range 引擎 | 可控但增加认证跳转、分片恢复、对象变更和错误处理责任 | 不建议替换 SLC；DEM 现有 Range 模块补合同即可 |
| 任意镜像/不明加速源 | 来源/身份、凭据和内容一致性难核对 | 不作为默认加速方式 |

推荐首版“均衡”参数是待验证的工程起点：SLC 同时 2 文件、每文件最多 4 段；DEM 同时 2 瓦片、每瓦片最多 2 段；整个应用最多 8 个数据传输连接，按主机公平调度。EOF 小文件单连接；各角色共享预算，不是 8+4 再无限叠加。服务方有更严格限制时优先遵守。最小 SLC 分片建议 16 MiB，避免海量小 Range；不支持 Range 时显式退为单流。

“稳定”模式 1 文件×2 段用于不稳定线路；不默认启动“最大线程数”。界面可设全局限速，显示当前有效吞吐、连接策略与暂停原因。连接数不等于速度，TLS/认证、服务端限流、RTT/丢包、代理链路、磁盘/防病毒、校验 CPU 和拼接 IO 都可能限速。

正常重试采用指数退避加抖动，尊重 Retry-After；429/503 降并发，401/403 分清凭据/授权/签名过期，最多触发一次相应重新认证/URL 刷新后向用户报告；404 区分源暂不可用与缺数据，不无限重试。

网络设置统一为直连/系统环境代理/手动代理，覆盖检索、认证、SLC、EOF 和 DEM。连接诊断只显示脱敏主机、DNS/TLS/首字节时延及错误分类，不打印代理账号或凭据。只有明确的用户网络选择才改变路由，不用禁用证书验证解决连接失败。

### 4.4 实现优先级

**P0：正确性与安全发布，先于提速。**

- 修复 ABCD EOF 精确映射；校验 XML 卫星、POEORB 类型、有效开始/结束覆盖 SLC 全成像时段；同一 EOF 多景引用去重。
- 已有 SLC 必须通过预期长度、ZIP 中央目录/CRC 与必要 SAFE 元数据检查；若提供方有摘要则比对。新下载也在发布前检查，损坏文件隔离保留，不能将非空当完成。
- 本地 SHA-256 可作内容身份，不得标为“提供方摘要验证通过”；未知源摘要单独记录。多 GB ZIP CRC/摘要检查是实际 IO 工作，进度显示“校验中”而非“下载卡住”。
- 分片 manifest 绑定源对象标识、总长、强 ETag/版本或可验证 Last-Modified；恢复时 If-Range/条件请求并检查 206 区间/总长。ETag 不是通用 MD5，弱验证器不能当强一致依据。对象变化隔离旧 partial，建立新尝试。
- 维持 HTTPS/TLS 校验，应用调用显式设定必要选项，避免用户 aria2 配置意外覆盖安全策略。凭据/带签名 URL/代理秘密不得进入公开日志、命令行展示、计划快照；临时 cookie/输入文件限制权限并清理。
- 按新内容版本发布，不让 overwrite 参数覆盖旧可用资产；控制与状态持久化继续保留独立尝试。

**P1：吞吐与复用。** 全局队列、公平并发、认证会话复用、统一代理、限速/退避；场景和 DEM 瓦片身份去重；网络与解码/拼接进度分开。

**P2：有证据的调优。** 后续在明确测试数据与目录下，用同一 ASF SLC 和公共 DEM 做 1×4、2×4 与稳定模式对照，至少 3 次且覆盖足够长的稳定区间；分别记录有效吞吐、耗时、重传/429/5xx、CPU/磁盘、校验耗时和中断恢复。只有大文件与平台实测后才调整默认值或宣称提速。本次不运行带宽饱和测试或修改用户代理/网络。

## 5. 接口、P02 交付与验收新增

获取 preview/plan 增加 include_orbits、include_dem 与 DEM policy（full_scene_union、buffer_m=20000、source_id=COP30）、network_profile 引用。前端冻结勾选/来源/余量；worker 不再硬编码 include_orbits=True。DEM plan 保存参与场景及完整几何版本、估计/已核对范围、瓦片清单/缺失原因、空间预算和输出高程参考。秘密仍在本机 provider，不嵌入 snapshot。

角色状态区分未请求、待 SLC 几何、源暂不可用、排队、传输、校验、拼接、已发布、失败；下载控制中的“暂停”指停止网络并保留 partial，不承诺 GDAL 可任意中断续算。拼接若中止从已校验瓦片重做，不重下 SLC。

P02 增加 DEM Library 引用、范围来源/余量、源版本、原始高程基准、nodata/缺瓦片报告与准备状态。P01 不选择参考影像、IW/burst 或处理参数，也不把 EGM2008 GeoTIFF 直接标处理就绪。
