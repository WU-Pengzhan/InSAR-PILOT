# InSAR-PILOT Web 版本阶段总结与后续工作评估

评估日期：2026-09-05。对象为当前本地工作树的 Web 迁移预览版，不代表 GitHub 已发布版本。本文是实施状态快照；目标架构仍以 [overview](overview.md) 为准，持续进度以 [migration](migration.md) 为准。

本次核对了领域模型、存储和处理服务、Web API、前端页面、测试配置及已有科学验收记录。没有重新下载 SAR 数据、启动科学计算或重新运行全部测试。下述测试和数值结果均注明为已有记录，不将不同批次测试数量累加成新的全量验收结果。

**结论：新架构核心已经落地，Web 版已能进行实际操作，并已有真实科学执行证据。当前适合受控试用和逐页完善，尚未达到全面替代旧版、面向普通用户稳定发布的门槛。**

## 1. 产品介绍与当前可用范围

InSAR-PILOT 正在从 Qt 桌面程序迁移为本机浏览器中的项目制 SAR/InSAR 工作台。用户在 Ubuntu 或 WSL2 Ubuntu 启动后台，通过浏览器管理数据、配置官方处理流程、查看任务、历史成果和 QC。应用环境与科学处理环境分开。

当前范围为数据获取 → 预处理 → 成果与 QC。Sentinel-1 保留官方 ISCE2 TOPS 路线；NISAR 保留官方 ISCE3 InSAR workflow。后处理只提供输入信息检查入口。

| 功能区 | 已实现能力 | 当前边界 |
|---|---|---|
| 启动、会话与退出 | Web 启动器、本机会话与 Origin 校验、重复连接、后台状态、明确退出入口、CLI 状态/停止 | 关闭浏览器不停止后台；活动任务需先暂停或取消；当前本机安装可用不等于新用户安装验收完成 |
| 工作台 | 项目导航、对象页面、可拖动和收起的属性栏、原项目 Logo、中英文和明暗主题 | 部分页面仍有英文、JSON 和内部字段，专业交互需要继续设计 |
| 文件选择 | 服务端目录浏览、位置侧栏、地址栏、面包屑、多选、固定尺寸及内部滚动 | Windows 浏览器选择的是 WSL 服务可访问的路径；不是把数据上传到浏览器 |
| 工程 | 创建、打开、最近工程、AOI/配置修订、数据绑定、mission Profile 锁定 | 首次正式绑定处理数据决定 mission；不同 mission 使用不同工程 |
| SAR 检索 | Sentinel-1/NISAR/All 分组检索；Sentinel A/B/C/D 多选；日期与任务筛选、结果分页和 footprint | ABCD 参数映射已验证，不保证每颗卫星在任意日期均有上游可检索产品 |
| AOI 与底图 | BBOX/WKT/KML/Shapefile、地图矩形绘制；Leaflet 检索地图与纯影像底图 | 保留来源署名，不叠加地名/行政边界；底图依赖网络可用性 |
| 数据入口 | 从检索选择创建工程、添加兼容工程、仅下载；本地数据导入和共享 Library 引用 | Library 版本管理与外部数据强校验仍需完善 |
| 下载管理 | 复用原 DownloadService/aria2c；Sentinel SLC/EOF、NISAR 完整 RSLC；清单、路径、速度、进度、暂停/继续/取消/重试 | 继续/重试保留旧尝试并创建新尝试；真实远程认证和传输闭环还需验收 |
| 处理计划 | 已准备输入的 Pipeline 配置、计划预览、冻结输入和配置修订、提交、扩大必要上游重算范围 | 当前仍需专业用户提供科学环境、模板及部分 JSON 参数；准备过程尚未全部界面化 |
| 任务与历史 | 无 Qt worker、独立工作空间、任务取消、日志、事件补读、Run 历史、重跑关系 | 完整崩溃注入、孤立输出恢复和长时间负载验收未完成 |
| 成果与 QC | Artifact 清单及资产依赖冻结、来源关系、结构门禁、部分 baseline/misregistration/产品指标、QC 重评 | 尚未覆盖两条流程全部阶段的版本化产品合同及专业 QC 矩阵 |
| 当前成果选择 | 符合当前输入/参数和门禁的成功结果成为 active；变更后的旧结果显示 stale | 旧 Run 的成功历史保留；还需把状态解释做得更容易理解 |
| GIS 与图表 | 产品预览、地图坐标/雷达坐标区分、图层登记、基础栅格访问和图表页面 | 当前影像显示使用有界采样；完整多图层交互、原分辨率窗口/瓦片和专业图表待补 |
| 旧工程与后处理 | 导入为新工程，保留来源与未知字段；可检查后处理输入 bundle | 不改写源工程；SBAS、时序反演、形变速率等尚未实现 |

一个专业用户目前可以创建工程，检索或导入数据，管理下载，使用准备好的 DEM、轨道、模板和科学环境配置流程，预览并提交计划，查看历史、日志、成果和已有 QC。**“从空白环境点击几次即可稳定生成两类卫星的最终合格产品”尚未完成。**

## 2. 底层建设成果

- 领域模型已区分 Project、Pipeline、Step、Run、Job、Artifact 和 QC，避免把流程步骤与一次执行混为一谈。
- 工程意图保存为 JSON，接受的修订与执行记录保存在 SQLite；已有修订检查、WAL、外键、pending 修订恢复和原子文件写入。
- 每次执行建立独立工作空间和日志，重试使用新 ID；已发布成果使用独立副本及清单，保留 XML/VRT 等物理依赖。
- 参数、输入版本、模板和运行环境信息参与科学签名；界面配色不导致重算，QC 重评追加报告。
- 官方处理器通过独立进程运行，浏览器断开不取消任务；已有进程身份、租约、取消和恢复观察机制。
- REST/WebSocket 和前端已接通；OpenAPI 类型生成及 Web CI 配置已加入仓库。完整响应类型覆盖仍在待办中。

这些能力解决了工程历史和可追溯性的核心问题，但不能据此推定所有断电、磁盘异常、进程丢失场景都已验收。

## 3. 科学执行达到什么程度

| 路线 | 已有真实证据 | 验收判断 |
|---|---|---|
| Sentinel-1 新引擎 | 16 个正式阶段均保留；样本前 15 步成功，第 16 步 SNAPHU 1.4.2 报尺寸超限；保留 1×1 looks | 整条科学回归未通过；没有为绕过失败而改变科学参数 |
| NISAR RIFG 新引擎 | 原继承线程环境下执行成功；相位圆周 RMSE 约 2.23×10⁻⁷ rad，相干性 RMSE 约 7.44×10⁻⁸ | 通过该样本及该环境记录的候选容差 |
| NISAR 完整产品执行 | CPU 执行成功并发布 8 个逻辑 Artifact，共用 RIFG/RUNW/GUNW 三个 HDF5 容器 | 证明执行和发布可用，尚未完成全部黄金数据数值验收 |
| NISAR 环境敏感性 | 四线程执行的 RIFG 相位差约 4.01×10⁻⁴ rad，超过原环境容差；GUNW 重复执行相位差约 3.94×10⁻⁴ rad，坐标轴与连通分量一致 | 原因仍待定位，不能把进程 SUCCESS 等同于黄金对照通过 |
| 旧链路 NISAR | 保留 CPU AOI 全流程与远程 Range 子集对照记录 | 是可迁移的既有能力和证据，不等于这些准备步骤已全部接入 Web |
| CUDA / HKIA | 尚无本次迁移所需的完整验收 | 不宣称支持已验收 CUDA 科学执行或已通过大批量性能测试 |

主要证据位于仓库 `artifacts/`：`nextgen-sentinel-regression.json`、`nextgen-nisar-rifg-regression.json`、`nextgen-nisar-products-regression.json`；旧链路记录为 `nisar-aoi-e2e-2026-09-04.json` 和 `nisar-remote-subset-comparison-2026-09-04.json`。GUNW 的重复执行对照不等同于旧版黄金数据对照。

## 4. 工程测试与平台验证

已有基线记录为旧环境 490 passed、1 skipped，以及独立 Web 环境 33 项测试通过。后续文件选择、会话、检索、下载控制及退出功能分别补充了针对性测试；最近退出功能记录为 13 项 Python 测试、13 项前端测试和 9 项浏览器用例通过。这些来自不同批次，不能累加成“当前全量测试通过数”。

浏览器验证包含 Linux Firefox/Chromium、Windows Edge 访问 WSL，覆盖若干 1440×900、1366×768 及紧凑视口、中英与明暗主题场景。文件选择还检查了 Linux 路径模式。未进行独立裸机 Linux 安装验收；完整原生 125%/150% 缩放、大列表、地图和 splitter 矩阵仍未全部通过验收。

已有记录包含 TypeScript/build、Ruff、适用 mypy 和 MkDocs strict 检查通过。下载控件的部分浏览器测试使用模拟 API；当前凭据存在与本地 aria2c 可用不能证明 Earthdata 远程认证成功。

## 5. 长期运行方面的剩余问题

原生日志持续保存到本机文件，日志 API 支持分页读取，状态事件单独持久化，因此不会把所有日志行直接灌进状态数据库。不过当前前端事件集合仍持续累积，每批新事件又触发工程、成果、历史等多项列表刷新。

这意味着任务和事件很多时，浏览器内存、页面渲染和本机请求可能增长；本地日志没有完善的自动归档/轮转政策时，磁盘使用也会增长。它是待处理的长期运行容量问题，不表示启动后马上发生通讯故障。

后续应补事件列表上限/虚拟列表、按游标加载历史、合并和节流刷新、大列表分页、容量监测，以及保留 Run 证据的日志归档规则。不能为节省空间直接覆盖历史科学日志。

## 6. 建议的后续实施顺序

| 优先级 | 工作包 | 完成标志 |
|---|---|---|
| P0：正式替代的阻断项 | 定位 Sentinel 解缠尺寸问题；定位 NISAR 环境敏感性并冻结环境与分指标容差；补 GUNW 黄金对照 | 两条 CPU 实际样本全流程通过，重跑不改变旧成果；保留失败证据 |
| P1：当前用户闭环 | 逐页完善数据集与附属数据准备、专业参数表单、计划预览和处理监控；接入 DEM 与 Range 子集 | 用户可以从数据选择走到可验证的准备输入，无需靠 JSON 拼接基本流程 |
| P1：真实获取验收 | Earthdata 认证、SLC/EOF 与 RSLC 实际下载、暂停/续传、跨工程复用 | 在独立小样本目录产生校验记录；界面与真实传输状态一致 |
| P1：可靠性 | 发布/队列崩溃注入、孤立成果核对、外部数据强校验、事件/日志容量管理 | 进程与存储异常后恢复确定，不误报成功、不重复执行、不覆盖历史 |
| P2：科研解释与空间体验 | 完整输出合同和 QC、baseline/配对图、成果对照、多图层、全分辨率空间读取 | 用户能解释结果是否可用、哪里异常、来自哪次运行 |
| P2：产品验收 | 补全翻译、响应类型与组件测试；Linux/WSL 安装、缩放和大列表矩阵 | 新用户按文档安装和操作无需人工修补环境 |
| P3：迁移与发布 | 旧工程导入验收、整理版本与发布包、全量回归、再切换默认入口 | 满足科学和用户闭环门槛后发布；对应替代能力合格后再移除 Qt |
| 后续扩展 | HKIA 批量性能、独立 CUDA 验收；按范围决定后处理扩展 | 各自有独立证据，不沿用 CPU 小样本结论 |

按逐界面设计的方式，建议下一页重点做“工程中的数据集与准备状态”：明确已选影像、参考/secondary、轨道、DEM、缺失项及下一步。随后完成处理参数与计划、运行监控、成果/QC、GIS。每页同时核对后端合同和异常状态，避免界面完成而实际步骤仍依赖人工操作。

## 7. 阶段判断与对外表述

架构设计已经形成统一依据；Domain/存储和 Job 核心已实现；Data/QC/GIS 与 Web GUI 属于功能子集和持续完善阶段；最终科学回归、默认入口切换、旧 GUI 清理尚未完成。当前工作树还包含大量修改和未跟踪文件，应在发布前整理和冻结可复现版本。

建议介绍为：**“InSAR-PILOT 下一代 Web 工作台已完成工程、数据检索与下载管理、任务历史及成果追踪的核心建设，已接入官方 Sentinel-1/NISAR 处理能力并开展真实数据验证，当前处于功能预览与迁移验收阶段。”**

不建议介绍为“两条处理链已全部验收”“已完全替代旧版”“已支持经验证的 CUDA”，也不宜用一个完成百分比掩盖未通过的科学门槛。
