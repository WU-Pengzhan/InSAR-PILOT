## 现有实现

- Domain/SQLite：工程 Profile 和修订、Run/Job 历史、基本 freshness、QC 与 active。
- 执行：独立工作空间、官方 TOPS 阶段、NISAR 官方 workflow、进程控制、日志和来源快照。
- 数据：全局/工程检索、Sentinel ABCD 多选、纯影像地图、本地导入、Library 引用、SLC/EOF 与完整 RSLC 下载核心。
- Web：工程页、文件选择、参数/计划入口、运行/成果/QC、可收起 Inspector、中英主题、下载管理与明确退出。
- 下载：冻结清单、状态/进度、暂停/继续/取消/重试；终态尝试保留。
- 退出：关闭浏览器不取消任务；空闲退出与意外断线区分；CLI --status / --stop。
- 历史迁移：导入新目录并保留来源；缺失历史不补造。

上述是功能子集，不能据此宣称下面的页面提案已全部实现。

## 接下来按页推进

1. 先讨论页面分工与 phase stack 合同；当前只交付文档和页面提案。
2. 确认后从“检索与下载”开始，针对 Sentinel 做本页设计、后端接线与验收。
3. 再做“数据与准备”，明确数据集、参考影像、目录、轨道、DEM、AOI/IW/burst 和缺失项。
4. 再做“参数与生成”，提供专业表单、计划和官方 run-file 预览。
5. 再做“运行”，明确阶段、批次、停止、重跑、检查与后台持续运行。
6. 再做“成果与 QC”，围绕确认的 phase stack 组织场景/配对、显示与有限范围检查。
7. Sentinel 页面闭环后，再规划 NISAR 专属页面和 openSEPPO 获取策略。

每次实现都先明确必要的领域/API 合同，再改 GUI。发现共享层缺口，只补足本页必要部分；不要自动启动剩余所有页面。

## 当前保留的工程验收

仍需验证输入绑定、重复提交保护、官方顺序和失败传播、输出可读/shape/sidecar、历史隔离、取消、会话与退出。根据改动运行针对性的 Python、前端、浏览器和静态检查。
大文件显示/统计按窗口、分块或采样设计，记录范围，不自动扫描整景。

长时容量、队列/发布崩溃恢复、外部数据强校验、专业参数表单、真实下载认证与续传、完整 UI 缩放/平台验收仍有待办。它们按页面依赖或独立维护任务安排。

## 不再使用的当前阻断项

不要求先修复 SNAPHU 解缠、先通过整套 GUNW/相位黄金对照、先完成两种传感器 GUI，才允许推进 Sentinel Web。
旧失败与数值差异记录保持不变；科学评价缺省为未执行/UNKNOWN，不改写成 PASS。
如果当前选定产品本身缺少必需输入、生成失败或不可读，仍然阻断该产品成功状态。
