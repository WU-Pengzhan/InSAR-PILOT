## 推荐交互
新建：工程名、保存父目录、mission/profile；实时显示最终工程文件位置。新建独立目录，拒绝覆盖已有工程。
打开：默认选择 *.pilot 文件，文件夹仍可导航；文件列表显示工程图标、文件名，选中后显示名称、Profile、版本和可打开状态。
最近工程：显示工程名、mission、文件路径、最近打开时间；按 project_id 管理身份，路径只是位置。
命名建议：新工程采用工程名.pilot，例如 YanAn.pilot；一个工程根目录只保留一个主工程文件。旧新版 project.pilot 继续可用，不自动改名。
名称与文件名解耦：修改显示名称不自动移动磁盘文件；重命名工程入口须通过应用维护引用，不复制产生第二个主文件。

## 打开合同与异常
先只读识别：可打开的 Web 工程 / 旧工程待导入 / 缺配套状态 / 格式错误 / 不支持版本 / 多入口冲突。
验证通过后再接受当前修订、恢复事务并注册；异常不得创建空数据库或自动伪造历史。
旧 GUI 工程：进入明确的“导入旧工程”流程，显示新目录、新 ID 和迁移限制，保留来源。
旧目录调用可作兼容入口：只接受唯一有效主文件；多个候选要求明确选择，不猜测。
只有 .pilot 而缺失数据库：提示工程不完整；可另行设计“从配置新建”，明确无法恢复 Run 历史，不自动执行。
同 ID 同位置重复打开复用现有工程；同 ID 不同位置需区分搬迁/副本，不默默覆盖注册或并行写入。
工程内受管理资源优先相对引用，外部 Library 数据保留版本与位置解析；移动后校验路径，缺失时提供重新定位。
搬迁应在任务停止、服务释放工程后进行；需迁移已有绝对路径引用并正确处理 SQLite WAL，不能宣称复制文件夹即完全可复现。
仅复制 .pilot 不等于完整备份。便携导出/另存工程副本留独立任务，需包含状态一致性和依赖清单。

## Linux 与 WSL
浏览器继续使用服务端文件选择器，不上传工程文件或科学数据。
Linux 浏览本机路径；Windows 浏览器连接 WSL 时浏览 WSL 服务可见目录，并提供 Windows 挂载盘入口。
工程状态优先存 WSL Linux 文件系统；沿用现有 host_path 映射。
操作系统双击关联属于后续启动器集成，不是更改扩展名后浏览器自动具备的能力。WSL/Windows 关联需要显式分发到正确发行版与已有服务。
