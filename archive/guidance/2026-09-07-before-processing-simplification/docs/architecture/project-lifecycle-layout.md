## 用户已确定的要求
- 启动先到工程选择首页，不自动打开上次工程。
- 未打开工程时，业务功能只开放检索与下载；P02—P05 依赖工程。
- 打开选择 .pilot 文件；新建选择保存位置并输入工程名称。
- 以工程目录统筹数据区 data 和处理区 processing；具体子目录及数据归属策略为下述设计建议。
- 保持五页划分、二进制 .pilot 和 Web 唯一方向。本轮不开展 P02 完整设计。

## 启动与页面状态（实施合同）
建议所有全新页面加载（包含浏览器刷新）进入 NO_PROJECT / Home；不恢复上次项目或页面。
现有主题、语言、分隔条宽度等外观偏好继续保存。仅 WebSocket 重连不清除当前工程、不抢页面。

首页只设三个主要操作：新建工程、打开工程、检索与下载；最近工程可点击打开。
最近工程卡显示名称、传感器、.pilot 位置、最近打开时间、可用性；增加基于数据库事实的简要状态，如“尚未绑定数据”“2 个后台任务”。没有证据不显示完成百分比。
读取最近列表不得隐式打开、恢复或修改工程。旧工程不可访问时卡片仍保留并说明原因。

| 状态 | 可用业务入口 | 行为 |
|---|---|---|
| NO_PROJECT | P01 检索与下载、下载任务/已下载数据 | P02—P05 保留名称但禁用，提示先打开或新建工程；工程树/Inspector 清空 |
| OPENING | 工程识别/加载反馈 | 只有成功后才切换当前工程；失败留在首页或原工程 |
| PROJECT_OPEN | 五个固定页面 | 显示工程名与路径；首次进入 P02 的工程摘要/准备入口，不自动执行处理 |
| SWITCHING / CLOSING | 原工程仍可识别 | 处理未保存表单后切换；后端任务不因关闭当前工程而取消 |

Home、设置/认证、帮助、退出与最小后台状态属于外壳功能，不受业务页面禁用限制。
后台状态可显示任务所属工程、名称和运行状态；NO_PROJECT 下不暴露科学参数编辑/提交入口。
如需处理旧工程的运行任务，点击明确的“打开所属工程”；不自动跳转。下载任务可在 P01 继续管理。

前端工程选择是浏览器会话状态，服务端已注册/运行的工程不是当前页面自动选择的依据。
工程关闭/切换须断开旧订阅、使过期请求失效，清空对象、计划、日志、图层、文件列表等工程作用域状态。
操作函数与页面路由均校验是否已有工程，不能只让按钮变灰。项目 API 继续要求精确 project_id；不引入全服务唯一 active_project，避免多浏览器互相抢工程。
同页面普通请求失败不主动关闭工程；认证/服务恢复按连接状态处理，保留显式打开动作的边界。

## 新工程目录建议（待实施）

```text
YanAn/
├── YanAn.pilot
├── data/                         # 工程输入与引用视图
│   ├── slc/                      # 原始 SAFE ZIP / SAFE
│   ├── orbit/                    # 原始 EOF
│   ├── dem/                      # 源 DEM
│   ├── aux/                      # AUX 等附属输入
│   └── aoi/                      # 本工程 AOI 文件
├── processing/
│   ├── preparation/<id>/         # 有版本的准备结果/报告
│   ├── plans/<plan_id>/          # 冻结的生成计划、配置与脚本
│   ├── workspaces/<execution_id>/# 每次执行独占的官方工作目录
│   └── runs/<run_id>/            # 运行快照、配置与日志
├── products/<artifact_id>/       # manifest 与已发布科学资产闭包
├── .insar_pilot/
│   ├── state.sqlite
│   └── transfers/               # 未完成下载/校验暂存，不能处理
└── cache/                       # 可重建预览、瓦片、统计
```

data 放输入，processing 放准备/执行工作，products 单独保存已发布成果，避免混在可反复改写的处理中间目录。
科学产物不因移到 products 就改变 Artifact 身份/完整性/lineage 合同。原始导入 Artifact 可指向 data 或外部注册资产，不强制再复制一份到 products。
processing/preparation 中可复用的准备结果须版本化、验证并登记其闭包；名字本身不是已验证检查点。
plans 是冻结的生成证据；实际官方 run_files 和运行相对路径布局在独占 workspace 内物化并核验，不能盲目从 plans 目录直接启动官方命令。
禁止把多次运行挤进一个可覆盖的 processing/run_files；官方 TOPS 一个 execution 内仍保留原本的阶段顺序/目录关系。
用户界面的工程树仍按数据、处理、成果语义呈现，Files View 才显示实际路径；不新增主页面。

## 数据归属与下载位置建议
- 无工程的 Download Only：继续保存到全局 Library；下载前显示目标位置，可供后续工程选择。
- 已打开工程且“下载到本工程”：新数据默认实际保存到 data 对应角色目录，下载计划冻结 project_id、目标角色、路径、版本及归属。
- 用户仍可明确选择“仅下载到共享 Library”；不能因为页面恰好开着工程，就把 Download Only 静默变成项目输入。
- 已有 Library/外部数据：默认引用精确版本，显示“共享引用/外部引用”及真实路径；data 可生成由程序管理的输入视图，不能假称文件已复制进工程。
- 如需“复制到工程”，使用独立 copy/reflink 并预估空间、校验完成再发布引用；不默认复制数 GB 数据，不移动或删除原数据。
- 本轮默认建议不是承诺整目录已可便携备份；含外部引用的工程须明确展示依赖。
- 数据身份及强/弱验证、可用性继续由统一 Library/Artifact 注册管理；同一内容可有多个位置，不能以位置当内容版本。
- 下载 Job 仍只有一份权威记录，沿用应用下载调度器，增加目标归属；项目记录绑定/获取计划引用，不复制第二个可变 Job。
- 计划提交后切换/关闭工程不改变下载目标；完成后只绑定原 project_id，不污染后来打开的工程。
- 同一数据跨工程请求需共享身份锁并等待/复用校验结果，或显式物化到各工程；不能通过新目录绕过下载去重。
- partial/坏文件不进入 data 的可处理列表；发布与注册失败可恢复，不能只凭文件存在绑定成功。
- 工程数据的同名不同内容拒绝覆盖，保存独立版本目录；取消不发布未完成数据。

## 后端改动边界与兼容
1. 外壳启动可先独立实现：移除自动选中、明确无工程状态、守卫/清理、最近状态与测试。不改变旧物理目录。
2. 目录实现引入统一 ProjectLayout 路径解析器；单独 storage_layout_version（建议旧为 1、新为 2），不能复用 .pilot 二进制容器版本表示目录版本。
3. 无 layout 字段的旧工程继续按旧根目录路径解析。旧快照绝对路径、sidecar 和历史日志保持；打开时不自动搬迁。
4. 新建目录、计划预览/提交、Run 日志、Artifact 发布/恢复、文件浏览、下载暂存和导入统一走布局解析；禁止部分模块仍硬编码旧根路径。
5. acquisition-preview/commit 增加目标归属/位置/物化方式和空间信息，提交复核冻结计划；磁盘需求未知时明确未知。不是本轮已存在 API 字段。
6. 目录存储仍遵循 .pilot + SQLite pending/修订事务、Artifact 两阶段发布恢复；网络文件系统约束保持。
7. 原工程搬迁另行任务；不移动 /home/griffin/insar_projects 下真实输入或黄金成果。

## 验收与分步任务
A｜工程入口：启动/刷新有旧 localStorage 仍在 Home；无工程所有入口守卫；打开/失败/关闭/切换清理；请求乱序不串工程；已有后台任务继续并可识别；无任务自动启动。
B｜新工程布局与数据归属：新建目录预览一致；旧工程原路径可打开；冻结目标、复用/复制/partial、同名版本、取消/失败恢复不污染工程；日志/Artifact 不覆盖历史。
后端变更先跑存储/恢复/下载/API 定向检查，再 Web 类型/构建与浏览器验证；Ubuntu Firefox/Chromium、Windows→WSL、中英/明暗/长路径/空与失败状态。
本设计未运行上述验收或任何 SAR 计算。建议下一次先实施 A，再实施 B，不夹带 P02—P05 全页开发。
