# Run、Job 与软件生命周期

Run 是科学执行记录，Job 是计算实体。下载 Job 可无 Run。
默认同一时刻一个重型科学任务，下载使用其有界内部并发。
Web UI 只调用 API；JobExecutor 启动独立进程组。

## 执行证据

冻结 run/pipeline/step/execution/重跑 ID、时间、完整参数与配置、输入身份/角色/版本、
cwd、argv、官方顺序和脚本摘要、运行环境及处理器版本、代码版本与脏工作树摘要/相关差异。
记录请求/实际计算模式、可取得的设备信息、退出码、日志、QC 和复现限制。
未知统计保持未知，凭据只留引用。

stdout/stderr 持续写独立文件；官方合并流如实标 combined。
只有进程结束、必要输出检查和发布完成后才进入成功终态。
退出 0 但必需产品合同失败，记录 FAILED/artifact_contract，保留 exit_code=0。

取消须确认进程组退出后再终结；未完成文件不发布为有效成果。
下载的暂停/继续保留 partial，并创建关联的新尝试；不承诺科学流程任意暂停恢复。

## 恢复、事件与退出

进程身份、启动时间、心跳和租约支持恢复观察与重复启动防护。
重启核对存活 worker；无法核实完成状态的已启动任务记 interrupted，不从目录推断成功。
未启动队列重新验证后才执行。完整异常注入和孤立产物恢复仍见实施待办。

事件采用 scope 单调序号，WebSocket 按游标补读和去重；日志不逐行进入 SQLite。
分页日志、刷新合并/节流、事件容量和大列表策略是长时运行合同，实际覆盖见 migration。

关浏览器不取消后台任务。明确退出操作检查活动任务和 worker，空闲时停止服务。
主动退出完成与意外断线分别提示。CLI --status / --stop 不隐式启动服务。
退出保留工程、历史和下载文件；运行任务通过 Jobs 先暂停/取消。

Run 终态、成果登记、QC 引用、active 与终态事件需保持统一事务边界。
