## 先统一三个概念

- 页面按用户任务划分：找数据、准备输入、配置生成、执行、查看成果。
- Recipe 表示科学处理方案，包含目标产品、参数和依赖；不等于一个页面。
- 官方 run file 表示执行命令与顺序。同一页面可以展示多个阶段，阶段历史仍分别保留。

采用五个常驻页面，允许直接切换和返回修改。导航表达顺序，但不做禁止跳转的“下一步”向导。修改输入后，明确显示旧计划/成果为何过期。

## 五页总览

| 页面 | 用户在这里解决的问题 | 核心内容 | 交付给下一环节 |
|---|---|---|---|
| 1. 检索与下载 | 找哪些数据、正在下载什么 | AOI/日期、Sentinel ABCD、轨道/模式/极化等筛选、覆盖图、场景清单、下载任务 | 场景选择、获取计划、可用数据位置与状态 |
| 2. 数据与准备 | 这个工程的输入是否齐全、是否兼容 | 本地/Library 引用，SLC/SAFE、Orbit、DEM、参考影像、AOI/IW/burst 分析，目录与环境概况 | 有角色和版本的输入绑定、缺失项与准备报告 |
| 3. 参数与生成 | 计算什么、用什么参数、将生成哪些命令 | 专业表单、参数帮助、目标产品/looks、环境、preflight、Generate、run-file 和重算范围预览 | 冻结的参数与官方执行计划；生成不等于运行 |
| 4. 运行 | 现在到哪一步、哪里失败、如何停止或重跑 | 正式阶段与分组、命令/批次、Job 状态、逐步基础检查、日志、取消与重跑计划 | 有出处的 Run 记录、已发布阶段成果 |
| 5. 成果与 QC | 拿到了哪些 phase stack 成员、怎样查看与使用 | 场景/配对列表、影像显示、来源、覆盖/形状/有效性、按需窗口或采样指标 | 可定位的成果与 metadata/manifest；后续导出形式另行设计 |

运行中的下载任务也可从全局 Jobs/状态栏进入，不要求用户一直停留在第一页。
工程打开、新建、设置、Compute、共享 Library 和文件浏览是外壳/辅助入口，不再增加五条同级“流程步骤”。

## 第 1 页：检索与下载

沿用现有 Leaflet 纯影像底图、AOI 工具、结果选择和下载控制；本页细化见 [P01 设计](p01-search-download.md)，首版聚焦 IW SLC，独立已选清单跨检索保留。
Sentinel 专属筛选与 NISAR 专属筛选分开，All 查询分组。一个混合检索列表不能直接绑定成混合处理工程。

首轮 Sentinel 重点：筛选字段与布局、场景识别与覆盖、选中清单、创建/添加工程或仅下载、下载准备与暂停续传。2026-09-06 用户新增可选 EOF/DEM：DEM 覆盖完整 SLC 联合范围并留余量，见[补充设计与网络评估](p01-ancillary-downloads.md)；P02 继续负责 DEM 高程基准与处理适用性。
检索中的 footprint/AOI 不代表已经下载 burst 子集；burst/IW 覆盖和共同可处理范围要与第二页输入验证衔接。

## 第 2 页：数据与准备

支持“刚下载”和“已有本地数据”两种入口。用户选择路径后，系统识别产品、显示角色和兼容原因，不能只展示一组空目录框。

建议分为数据集表、附属数据、空间/时间兼容性和准备状态四块。参考影像选择归此页；第三页展示其摘要，不另存冲突设置。第二页查看环境可用性，第三页选择并冻结具体 RuntimeProfile。

DEM 自动准备若尚未接线，应明确显示可选已有 DEM 和待实现状态；轨道、DEM 可用性不通过时不能生成假“就绪”。具体垂直基准证明方式在本页设计时确定。

## 第 3 页：参数与生成

同一页采用“参数设置 / 生成预览”两个子视图，暂不新增第六个主页面。
处理方案和科学参数提供解释、单位、适用条件和已解析默认值，JSON 只保留为高级检查入口。

Generate 使用官方生成器，不自行编造 run-file 内容。预览给出参考影像、输入版本、目标产品、官方阶段、输出位置、必要上游重算范围和资源估计（未知则标未知）。提交运行必须引用该版本计划。

具体参数清单在本页实施时审计现有 generator 与官方能力，不在页面划分阶段预先承诺所有 Recipe。

## 第 4 页：运行

正式阶段可按准备/几何、配准、合并、干涉等科学分组呈现，但每个实际阶段都保留命令、Run、日志和基础检查。
选中阶段可看 acquisition/pair 和子命令批次；无可靠总量时显示活动阶段，不猜百分比。

“取消”与“重新运行”要说明实际作用和新增目录。未验证的中间检查点不能直接跳过依赖。
科学处理的暂停/恢复不沿用下载暂停语义，也不在此方案中承诺任意断点恢复。

每步检查包括真实退出状态、必需成果和结构；需要昂贵相位统计的检查显示未执行。
解缠和后处理不属于当前近端目标，历史记录仍可查看。具体在哪里停止执行，须由已确认产品合同和官方计划能力共同决定。

## 第 5 页：成果与 QC

一个成果列表同时展示场景日期或配对、产品类型、looks/网格、Run 来源和当前适用性；QC 作为成果详情/子视图，不让用户在几个页面重复查同一个对象。

显示复数 SLC 相位与显示干涉相位必须明确区分；原始复数资产不能被一张相位 PNG 取代。
雷达坐标影像使用影像视图，有可靠地理定位时才进入地图；不伪造地理 CRS。

大数据优先按窗口/分块/抽样显示和统计，标注 mask、nodata、范围和采样方法。整景数值对照不自动运行。
当前只检查和展示约定的 stack 成果，不增加 SBAS、时序或速度图按钮。

## 已确认与仍未决的事项

- 已确认五页顺序/职责，Recipe 不与页面一一对应。
- 第三页采用“参数设置 / 生成预览”；第五页同页组织成果与 QC，第四页呈现逐步基础检查。详细布局在各页设计任务中落实。
- 每次只做一个页面任务，默认先开展 P01；确认页面结构不等于一次授权实施全部页面。
- phase stack 首要交付配准 SLC、缠绕干涉相位还是两者，仍待明确选择；这是交接索引 D01，不阻挡 P01 和通用输入管理。
- 每页细化后的设计/API/验收记录由[任务卡与索引](../handoff/index.md)接续；不在旧对话里寻找未落盘的隐含决定。

## 单页完成的判据

有明确输入/输出、后端合同、正常与空/加载/失败状态、返回修改后的状态传播；
布局适合 Linux Firefox/Chromium 与 Windows 浏览器访问 WSL；
完成与改动相称的测试、类型/构建和浏览器检查；在 migration 中更新本页的真实状态。
页面结构确认不代表实现通过，界面测试通过不代表未经执行的科学验收通过。
